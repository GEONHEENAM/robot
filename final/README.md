# 협동로봇(M0609) 비전·음성 집기 프로젝트 — 1~6단계 코드

고정 USB 웹캠으로 테이블 위 막대를 찾고, 음성·텍스트 명령이나 GUI에서 고른 막대를
두산 M0609가 집어 지정 칸에 놓는다. "길이 순서대로 정렬해"로 여러 막대를 길이순으로 배열할 수 있다.

퀴즈3 구조를 그대로 따른다: **DRL이 TCP 서버(포트 9000), PC GUI가 클라이언트.**

## 파일 구성

| 파일 | 단계 | 역할 |
|---|---|---|
| `config.py` | 공통 | IP·포트·카메라·작업 영역·놓기 칸. **값은 여기 한 곳만 고친다** |
| `vision.py` | 1 | 막대 검출, 픽셀↔로봇 좌표 변환, 화면 표시. 단독 실행으로 파라미터 조정 |
| `final_gui.py` | 2, 4 | 메인 GUI (퀴즈3 GUI 기반 + 카메라 화면 + 스냅샷/선택/PICK) |
| `fake_robot.py` | 2 | 가짜 로봇 서버. 로봇 없이 GUI·캘리브레이션 흐름 테스트 |
| `drl/main.drl` | 3 | 퀴즈3 DRL + HOME / PICK / MOVEXY / GETPOS |
| `robot_link.py` | 3 | 스크립트용 로봇 소켓 클라이언트 |
| `robot_test_client.py` | 3 | 터미널에서 DRL 명령을 한 줄씩 보내는 테스트 도구 |
| `calibrate.py` | 3 | 카메라↔로봇 캘리브레이션 (calib/H.npy 생성) + 검증 모드 |
| `intent.py` | 5 | 문장 → 의도 (규칙 기반 키워드). 단독 실행으로 문장 해석 확인 |
| `planner.py` | 5 | 의도 + 검출 목록 → 실행 계획 (애매하면 거부, 정렬 시 다음 막대 재매칭) |
| `stt.py` | 6 | Vosk 한국어 음성 인식 + 녹음. 단독 실행으로 인식률 테스트 |

실행 중 생기는 파일: `vision_params.json`(검출 파라미터), `calib/`(H.npy, 보고서, 결과 사진), `captures/`(저장 프레임), `logs/`(명령 이력, STT 테스트 결과)
직접 넣어야 하는 폴더: `models/vosk-model-small-ko-0.22/` (6단계)

## 1단계: 막대 검출 (노트북 카메라로 가능)

```
python vision.py              # 카메라 0번
python vision.py --camera 1   # USB 웹캠
```
- `params` 창 트랙바로 색(HSV)·최소 면적·가로세로비를 맞춘다. `m`으로 마스크를 보면서 막대만 흰색이 되게.
- `p`로 저장하면 GUI도 같은 값을 쓴다. `s`로 프레임 저장, `d`로 검출 목록 출력.
- 캘리브레이션 전에는 **임시 변환**이라 mm 값은 의미 없다. 검출과 각도 표시만 확인.
- 노트북 카메라는 개발용. 웹캠이 오면 색 범위를 다시 맞출 것.

## 3단계: DRL 확장 + 캘리브레이션 (로봇 필요)

### 3-1. DRL 올리기
`drl/main.drl` 내용을 DART-Studio 프로젝트(PJ3 복사본 권장)의 main.drl에 넣고 실행.
작업1·작업2 코드는 퀴즈3 그대로라 기존 기능도 같이 쓸 수 있다.

### 3-2. DRL 명령 단독 확인
```
python robot_test_client.py
```
아래 순서로 한 줄씩 입력하며 확인한다.

1. `HOME` → `AT_HOME`이 오는지
2. `MOVEXY,0,490,30` → 그리퍼 중심이 집기 영역 가운데 30 mm 위에 오는지 (TCP가 그리퍼 중심으로 설정돼 있는지 확인)
3. 막대를 각도 0°로 놓고 `PICK,0,490,0,2` → 손가락이 막대를 **가로질러** 잡는지
   - 막대와 나란히 잡으려 하면 DRL의 `YAW_OFFSET`을 90 → 0으로
4. 막대를 비스듬히(+30° 정도) 놓고 `PICK,0,490,30,2` → 그리퍼가 막대 방향을 따라 도는지
   - 반대로 돌면 `YAW_SIGN`을 1.0 → -1.0으로
   - ※ 3, 4번의 각도는 캘리브레이션 후 GUI가 계산해 주는 값으로 다시 확인할 것
5. 너무 얕게 잡히면 `GRIP_OFFSET`(접촉 높이보다 더 내려갈 깊이)을 조금씩 올린다. 막대가 MIN_DEPTH(7.5 mm)보다 얇으면 손가락이 테이블에 닿을 수 있으니 주의.

**DRL의 `PICK_X_RANGE`, `PICK_Y_RANGE`는 `config.py`와 같은 값이어야 한다.**

### 3-3. 캘리브레이션
웹캠을 삼각대에 고정하고 자동초점·노출을 고정한 뒤:
```
python calibrate.py --camera 1 --tol 3
```
1. 로봇이 집기 영역의 9개 점으로 차례로 내려간다.
2. 그때마다 그리퍼 중심 바로 아래에 마커(검은 원 스티커 등)를 붙이고 Enter.
3. 로봇이 홈으로 비키면 사진 창에서 마커를 **번호 순서대로** 클릭 → Enter.
4. 점별 오차(적합 / 교차검증)와 판정이 나온다. 통과하면 `calib/H.npy` 저장.

- `--tol`은 (그리퍼 벌림 폭 − 막대 폭) / 2 보다 작게 잡는다.
- 교차검증 오차가 실제 정확도에 가깝다. 한 점만 크게 튀면 그 마커를 다시 붙인다.
- 삼각대를 건드렸으면 **무조건 다시** 한다.

검증:
```
python calibrate.py --verify --camera 1
```
화면에서 점을 클릭 → 로봇이 그 위로 내려감 → 실제 어긋남을 자로 재서 기록.

## 4단계: 실제 연동

1. `python final_gui.py` → 카메라 번호를 웹캠으로 → 카메라 시작
   - 좌표 변환 표시가 **"캘리브레이션 적용"**인지 확인 (아니면 카메라 정지 → 시작)
2. 로봇 IP(config.ROBOT_IP) 연결 → READY
3. **[HOME 후 스냅샷]** → 표에서 막대 선택 → 놓을 칸 → **[선택한 막대 집기]**
4. PICK이 끝나면 DRL이 홈으로 돌아가 `AT_HOME`을 보내고, GUI가 자동으로 새 스냅샷을 찍는다 (`PICK 후 자동 스냅샷`).
5. "명령 이력" 탭 → CSV 저장. 무작위 위치·각도로 20회 이상 시도해 성공률표를 만든다.

GUI 안전장치
- 로봇이 움직인 뒤 찍은 스냅샷이 아니면 PICK을 거부 (막대 위치가 바뀌었을 수 있음)
- 집기 영역 밖 막대는 회색 표시, PICK 거부 (DRL도 한 번 더 검사)
- 실행 중에는 다른 명령 버튼 비활성화. **정지는 비상정지 버튼으로** (DRL은 동작 중 소켓을 읽지 않음)

## 통신 프로토콜

| 방향 | 메시지 | 의미 |
|---|---|---|
| PC → 로봇 | `TASK,1` / `TASK,2` | 퀴즈1·퀴즈2 작업 (기존) |
| | `HOME` | 홈 이동 |
| | `PICK,x,y,angle,slot` | 로봇 좌표 (x, y) mm의 막대를 angle(°, −90~90) 방향에 맞춰 집어 slot(1~3) 칸에 놓기 |
| | `MOVEXY,x,y,z` | 캘리브레이션용 이동 |
| | `GETPOS` | 현재 위치 요청 |
| | `END` | DRL 종료 |
| 로봇 → PC | `READY` | 접속 직후 |
| | `POS,x,y,z,j1..j6` | 현재 위치 |
| | `AT_HOME` | 홈 도착 = 촬영해도 되는 시점 (HOME 끝, PICK 끝, PICK 실패 후) |
| | `DONE,1` `DONE,2` `DONE,3` `DONE,9` | 작업1 / 작업2 / PICK / MOVEXY 완료 |
| | `ERROR,...` | 실패 |
| | `MEAS,z` | PICK 중 접촉 높이 |

PICK 성공 시 순서: `PICK Accepted…` → 진행 메시지 → `MEAS,z` → … → `AT_HOME` → `DONE,3`

## 아직 검증하지 않은 것 (현장에서 확인)

- `drl/main.drl`은 문법(파이썬 구문)과 흐름만 확인했고 **실제 컨트롤러에서는 아직 실행하지 않았다.**
  `float()`, `str.split()`, `try/except` 같은 파이썬 기능이 DRL에서 그대로 되는지 첫 실행 때 확인할 것.
- `YAW_SIGN`, `YAW_OFFSET`, `GRIP_OFFSET`은 그리퍼 장착 방향과 TCP 설정에 따라 달라진다.
- 노트북 내장 카메라는 자동초점·노출 끄기가 안 먹히는 경우가 많다. 웹캠으로 다시 확인.
- 놓기 칸(y=600)과 집기 영역(y 420~560)이 실제 테이블에서 겹치지 않는지, 로봇 도달 범위 안인지 확인.

## 5단계: 텍스트 명령 (해석기)

GUI의 "음성 / 텍스트 명령" 입력란에 문장을 쓰고 Enter.
```
python intent.py      # GUI 없이 문장 해석만 확인
```

처리 흐름: 문장 → **해석**(무슨 명령인지) → 새 스냅샷 → **계획**(어떤 막대를 어느 칸에) → 화면에 주황 테두리로 표시 → **[승인]** 또는 "실행" → 실행

| 말할 수 있는 것 | 예 |
|---|---|
| 위치로 집기 | 왼쪽 막대 집어 / 오른쪽 거 가운데에 놔 |
| 길이로 집기 | 긴 막대 집어 / 제일 짧은 막대 왼쪽에 놔 |
| 순서로 집기 | 두 번째 막대 집어 (작업자 기준 왼쪽부터) |
| 칸 지정 | 긴 막대 1번 칸에 옮겨 / 가운데 막대 P2에 놔 |
| 정렬 | 길이 순서대로 정렬해 (짧은 것 → P1) / 긴 것부터 정렬해 |
| 홈 | 홈으로 가 / 처음 위치로 (승인 없이 바로 실행) |
| 승인 / 취소 | 실행, 응, 네 / 취소, 아니, 그만 |

- 칸을 말하지 않으면 수동 조작의 "놓을 칸"을 쓴다.
- **애매하면 실행하지 않고 이유를 보여준다.** 막대 2개에 "가운데", 좌우 위치 차이 25mm 미만, 길이 차이 5mm 미만, 막대 수 > 칸 수(정렬) 등.
- 정렬은 PICK을 한 번씩 보내고, 매번 홈 복귀 → 새 스냅샷 → 다음 막대를 다시 찾아서(위치 25mm 이내) 집는다. 못 찾으면 중단.
- 연속 실행 중 "취소"는 **진행 중인 PICK이 끝난 뒤** 멈춘다. 즉시 정지는 비상정지 버튼.
- `config.LEFT_IS_POSITIVE_X`: 작업자가 서는 자리에서 로봇 +x가 왼손 쪽이면 True. **현장에서 꼭 확인** (틀리면 왼쪽/오른쪽이 반대로 동작).

## 6단계: 음성 명령 (STT)

### 설치 (인터넷 되는 곳에서 한 번)
```
pip install vosk sounddevice
```
1. https://alphacephei.com/vosk/models 에서 **vosk-model-small-ko-0.22.zip** 다운로드
2. `final\models\` 폴더를 만들고 그 안에 압축 해제 → `final\models\vosk-model-small-ko-0.22\` 안에 `am`, `conf` 같은 폴더가 보이면 정상
3. 이후에는 인터넷 없이 동작

### 인식률 테스트 (1일차에 먼저)
```
python stt.py --devices      # 마이크 번호 확인 → 필요하면 config.STT_DEVICE에 입력
python stt.py                # Enter로 녹음 시작/끝, 인식 결과·해석·시간 확인
python stt.py --test 5       # 명령 10개 × 5회 → 정답률표 (logs/stt_test_*.csv)
python stt.py --test 5 --mode free   # 문법 제한 없이 비교
```
- 기본 모드 `grammar_then_free`: 명령어 단어로 제한해 인식 → 결과가 비면 제한 없이 재인식.
- 문법 제한은 정해진 명령에 강하지만, **엉뚱한 말도 비슷한 명령으로 바꿔 버린다.** 그래서 GUI는 항상 승인을 받는다.
- 두 모드 정답률을 비교해서 `config.STT_MODE`를 정하고, 결과표는 발표 자료로 쓴다.

### GUI에서
- 시작할 때 모델을 자동으로 불러온다 (몇 초). "STT 준비됨"이 뜨면 사용 가능.
- **Space를 누르고 있는 동안 녹음 → 떼면 인식.** 입력란에 글을 쓰는 중에는 Space가 녹음으로 동작하지 않는다.
- 버튼 [누르고 말하기]를 마우스로 누르고 있어도 같다.
- 모델이나 패키지가 없으면 "STT 꺼짐 (텍스트 입력만)"으로 표시되고 텍스트 명령은 그대로 쓸 수 있다.
- 시끄러운 실습실에서는 노트북 내장 마이크보다 헤드셋 마이크가 확실히 낫다.

## 아직 검증하지 않은 것 (5·6단계)

- Vosk 한국어 모델로 실제 음성을 인식해 보지 못했다 (작성 환경에서 모델 다운로드 불가). 인식기 로직은 가짜 인식기로, 해석기는 문장 46개로 테스트했다.
- 문법 제한 모드가 한국어 소형 모델에서 동작하지 않으면 자동으로 자유 인식만 쓴다 (작업 로그에 표시).
- 정렬 전체 흐름은 가짜 로봇으로만 확인했다. 실제로는 앞 막대를 집다가 옆 막대를 건드리면 재매칭이 실패해 중단될 수 있다 → 막대 사이 간격을 충분히.
